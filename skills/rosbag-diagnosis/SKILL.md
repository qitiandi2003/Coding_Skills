# 用录包定位首个异常

1. 从用户描述的地点、动作或界面事件反查录包与日志。核对录制时段、地图版本、话题、消息数和时钟来源。如果日志用墙钟、录包用消息时间，先找共同事件对齐时间线。
2. 围绕首次异常截取前后窗口，按传感器输入、坐标变换、定位、规划、控制和界面逐段比对。找出哪个环节最先偏离预期。例如界面显示“已到达”时，检查同一时刻的定位、目标误差、判定条件和状态转换。
3. 为候选原因选择能区分它们的观测。障碍导致的停顿要能对应当时机器人轮廓内的点、坐标变换和规划器给出的阻塞原因。输入缺失或时间不同步时，记录缺口，再决定是否值得改阈值。
4. 需要回放时，使用独立 ROS 域、回环通信和临时输出目录，确认没有连到设备的控制桥。保留原包和基线配置。在相同输入、起点和窗口比较修复前后，再选曾正常工作的片段做回归。
5. 报告故障发生的时间、触发条件、首次异常和修复后的可测结果。区分构建、离线回放与真机验收。实际启动定位、导航或行走按用户对设备操作的授权执行。
