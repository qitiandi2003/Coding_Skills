# 用录包定位首个异常

1. 从用户描述的地点、动作或界面事件反查录包与日志。核对录制时段、地图版本、话题、消息数和时钟来源。如果日志用墙钟、录包用消息时间，先找共同事件对齐时间线。事件时刻不明确时，可以把最吻合的片段作为起点并说明依据。如果几个片段都吻合，先做能区分它们的离线检查，仍无法判断且选择会改变结论时再提问。
2. 围绕首次异常截取前后窗口，按传感器输入、坐标变换、定位、规划、控制和界面逐段比对。找出哪个环节最先偏离预期。例如界面显示“已到达”时，检查同一时刻的定位、目标误差、判定条件和状态转换。
3. 为候选原因选择能区分它们的观测。障碍导致的停顿要能对应当时机器人轮廓内的点、坐标变换和规划器给出的阻塞原因。输入缺失或时间不同步时，记录缺口，再决定是否值得改阈值。
4. 需要回放时，使用独立 ROS 域、回环通信和临时输出目录，确认没有连到设备的控制桥。保留原包和基线配置。在相同输入、起点和窗口比较修复前后，再选曾正常工作的片段做回归。
5. 跟进长时间的回放和验证，直到得到结果并完成约定的对比。遇到可恢复的失败，在授权范围内修正后重试。需要设备许可或缺少关键数据时，先完成能独立推进的离线检查。实际启动定位、导航或行走按用户对设备操作的授权执行。
6. 把最终回复写成可独立阅读的故障说明。先讲机器人当时做了什么、何时触发、哪个环节最先异常，再给出验证结果和采用的假设。用可观察的行为解释专业术语，展开排查时的临时缩写。交代哪些结果来自构建、离线回放或真机，以及哪些结论还缺证据。
